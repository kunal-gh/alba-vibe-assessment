# Alba Submission Health Report

Assignment 3 is an n8n automation workflow that produces a submission-readiness report from live GitHub data. It follows Alba's suggested "repo activity report" direction: pull real external data, transform it, branch on logic, handle failures intentionally, and return a report that can be verified immediately.

The workflow does not require any API keys. That makes it easier for reviewers to import and execute without connecting external credentials.

## What it does

The workflow checks the public repository `kunal-gh/alba-vibe-assessment`, fetches recent commit activity from the GitHub REST API, calculates a readiness score, and returns a compact JSON plus Markdown report.

If GitHub is unreachable, commit data is missing, or the repo looks stale, the workflow branches into an `ATTENTION` response. Otherwise it returns `READY`.

## Requirements coverage

| Alba requirement | Implementation |
| --- | --- |
| Trigger | Manual trigger for reviewer testing and Webhook trigger for live execution |
| External data | Two HTTP Request nodes call the public GitHub REST API |
| Transformation | Code nodes normalize repo metadata, dedupe recent commits, calculate age and score, and format a report |
| Conditional logic | IF node routes `READY` vs `ATTENTION` reports |
| Error handling | HTTP nodes use `continueOnFail`; the report builder detects API failures and sends the handled `ATTENTION` branch instead of failing silently |
| Verifiable output | Webhook response returns JSON and Markdown; manual execution shows the same payload in n8n execution data |

## Node-by-node walkthrough

1. **Manual Test Trigger**: lets a reviewer run the workflow from inside n8n without setting up any credentials.
2. **Live Webhook Trigger**: exposes a GET webhook at `/webhook/alba-submission-health` once the workflow is activated.
3. **Set Run Context**: records whether the execution came from manual testing or the live webhook.
4. **Fetch Repo Metadata**: calls `GET https://api.github.com/repos/kunal-gh/alba-vibe-assessment`.
5. **Fetch Recent Commits**: calls `GET https://api.github.com/repos/kunal-gh/alba-vibe-assessment/commits?per_page=5`.
6. **Build Submission Report**: transforms the API responses into a normalized report with score, status, recent commit summaries, and failure flags.
7. **Report Ready?**: branches into the `READY` or `ATTENTION` path.
8. **Prepare Ready Response / Prepare Attention Response**: adds reviewer-facing copy and severity.
9. **Webhook Request?**: sends webhook executions to a response node and manual executions to an output node.
10. **Respond with Health Report**: returns the live JSON response.
11. **Manual Evidence Output**: leaves the same report visible in the n8n execution panel for screenshots.

## Setup

1. Open n8n.
2. Import [n8n/alba_submission_health_workflow.json](./n8n/alba_submission_health_workflow.json).
3. No credentials or environment variables are required.
4. Activate the workflow.
5. Copy the production webhook URL from the **Live Webhook Trigger** node.

The expected production URL shape is:

```text
https://YOUR-INSTANCE.app.n8n.cloud/webhook/alba-submission-health
```

## How to run

Manual verification:

1. Open the workflow in n8n.
2. Click **Execute workflow**.
3. Open the **Manual Evidence Output** node.
4. Confirm it contains `status`, `score`, `recentCommits`, and `markdownReport`.

Live verification:

1. Activate the workflow.
2. Open the production webhook URL in a browser.
3. Confirm the browser returns JSON with `status`, `score`, and `markdownReport`.
4. Capture the n8n execution view and the webhook response for the Loom walkthrough.

## Known limitations

- The workflow uses GitHub's unauthenticated public API, which is rate-limited. This is acceptable for reviewer/manual runs.
- The n8n production webhook URL is generated by the reviewer/deployer's n8n instance, so it is not committed in the repository.
- The workflow reports repository activity and readiness signals; it does not replace manual verification of the deployed Vercel and Supabase apps.
